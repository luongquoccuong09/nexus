# M6 — Calendar and Meetings

The [roadmap](../ROADMAP.md#m6--rich-chat-calendar-and-meetings) tracks the initial calendar and meeting release in `M6.10`–`M6.15` and further capabilities in `M6.35`–`M6.39`.

## Delivery sequence

| Item | User flow | Acceptance |
|---|---|---|
| **M6.10 Component evaluation** | Two test accounts join a meeting on the candidate deployment. | Verify voice, camera, and screen sharing, including permissions in the browser and Windows Desktop WebView2. Test a VPN or network with UDP blocked, active participant removal, and rejoin with a previously issued credential. Document license, supported releases, deployment and update process, measured resource use, and estimated bandwidth cost. Record which components meet these requirements before integrating them. |
| **M6.11 Calendar and RSVP** | Create, update, or cancel an event. Invite eligible attendees, respond Going, Tentative, or Declined, and find the event in week, month, or agenda view. | Display the same event at the correct local time for each user. Verify attendee visibility and Community or Organization membership changes. Use the M4 outbox and notifications for invitations, changes, cancellations, and reminders. Recheck access before delivery and deduplicate retries. |
| **M6.12 Scheduled meetings and Meet now** | Join a scheduled meeting from Calendar, or start and join a meeting in an authorized conversation. | The same room supports microphone, camera, and screen sharing. Attendees can leave and an authorized host can end the meeting. A forwarded Nexus link requires the recipient's own authorization. |
| **M6.13 Direct calls** | Start a voice or video call from an eligible DM. The recipient can accept or decline, and either participant can share a screen or end the call. | Cancel, decline, timeout, and answer on one device clear ringing on the other devices. Handle simultaneous actions without duplicating the call or missed-call entry. Respect DM blocking and rate-limit initiation. |
| **M6.14 Recurrence and export** | Schedule a series, edit or cancel one occurrence, and download an `.ics` file. | Verify time zones, daylight-saving changes, recurrence exceptions, stable event IDs in exports, and data visibility. Bound occurrence expansion to the requested date range. |
| **M6.15 Release verification** | Exercise Calendar, scheduled meetings, Meet now, and direct calls on supported browsers and Windows Desktop. | Verify device permission denial and recovery, concurrent devices, reconnect, room isolation, and authorization changes. Record measured room size and concurrent-call limits in the target environment. Include the results in M8 review if these features are in the pilot. |

## Integration boundaries

- Nexus owns the event, attendance, invitation, room access, ringing and call state in the modular monolith. PostgreSQL stores durable product state. Existing SignalR connections deliver authorized call and event updates. The approved media provider carries audio, video, and screen sharing.
- Calendar items belong to an authorized Personal or Organization scope. Community events inherit Community access. Check the current account and resource permissions for event reads and writes, RSVP, notifications, and call initiation. Store timed event instants and the event time zone needed for display and recurrence. Cap list pages at 50 results.
- Before issuing a short-lived, room-scoped join credential, recheck the active account and meeting access on the server. Verify that disabling the account or revoking the relevant access removes the participant and prevents rejoin, including with old credentials. Keep provider secrets server-side and exclude tokens from logs.
- Test camera, microphone, and screen capture permissions on Nexus Desktop WebView2 as well as web. If the provider uses an embedded frame, allow only the approved origin and required capabilities. Capture begins through the user's explicit interaction with the browser or Desktop permission UI. [WebView2 screen capture](https://learn.microsoft.com/en-us/dotnet/api/microsoft.web.webview2.core.corewebview2.screencapturestarting)
- Evaluate a dedicated media endpoint for HTTPS, WebRTC UDP, TURN/TLS, and expected egress. Verify corporate network fallback in staging. Confirm the approved region and operating cost before enabling media in a real-data environment.

## Deferred capabilities

- Evaluate meeting chat and recap, live captions, recording and transcription, breakout rooms, and whiteboard or task integrations after validating demand. Check the approved upstream provider first. For stored media or transcripts, decide consent, access, retention, quotas, and deletion before adding them to delivery scope. [Teams meeting recordings](https://support.microsoft.com/en-us/teams/meetings/start-stop-and-find-meeting-recordings-in-microsoft-teams) · [Teams breakout rooms](https://support.microsoft.com/en-us/teams/meetings/manage-breakout-rooms-in-microsoft-teams)
- External meeting guests require a separate decision on identity, scoped invitation, expiry, access revocation, and guest visibility. The scheduled meeting and call flows in this plan use eligible Nexus accounts.
