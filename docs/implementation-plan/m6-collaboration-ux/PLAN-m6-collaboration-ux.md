## First implementation session — M6.16 Chat and Files pagination

- **Entry points.** Open Chat and its Files drawer in the SPA. Start in [`chat.tsx`](../../../src/Nexus.Client/src/chat.tsx), [`ConversationEndpoints.cs`](../../../src/Nexus.Web/Modules/Conversations/ConversationEndpoints.cs), and [`FilesEndpoints.cs`](../../../src/Nexus.Web/Modules/Files/FilesEndpoints.cs). The Chat request uses the Personal route for the unified list. Apply the conversation list behavior to both existing scoped routes.
- **Current behavior.** `loadConversations` and `loadConversationFiles` request 50 items. The conversation list returns the most recent page, and Files returns a pagination position that the drawer currently ignores. Message history already offers **Load older messages**.
- Add a stable cursor to conversation listing. Use a deterministic secondary key for tied activity times and preserve the first-page response for existing callers. In the Files API, keep existing timestamp pagination usable while handling equal creation times without skipping entries. Recheck the actor and resource access on each page.
- Add a keyboard-accessible **Load more** action with loading, retry, and end-of-list states. Append and deduplicate by ID. Keep selected chat, its loaded results, unread state, and scroll position during refresh. Ignore stale responses after scope or conversation changes. Keep sidebar filtering usable when matches are on later pages, either by querying the scoped list or by continuing to expose paging while a filter is active.
- **Acceptance.** Seed one account with more than 50 eligible conversations and one conversation with more than 50 attachments, including ties at page boundaries. Reach the oldest chat and file through the UI. Verify stable pagination with ties, no duplicates after a realtime refresh, and no stale results after switching accounts or losing access. Exercise keyboard loading, failure and retry, and a zero-result filter that can still reach later matches. Keep every request at 50 entries or fewer.
- **Targeted checks.** Extend the existing [`MessagingM2Tests`](../../../tests/Nexus.IntegrationTests/MessagingM2Tests.cs) and [`FilesM3Tests`](../../../tests/Nexus.IntegrationTests/FilesM3Tests.cs) for the page boundaries and scope checks. Verify the actual Chat and Files entry points with two scoped test accounts. Update the [HTTP API contract](../../API_CONTRACTS.md) with the chosen cursor shape when the implementation lands.

```powershell
dotnet test tests/Nexus.IntegrationTests --filter 'FullyQualifiedName~MessagingM2Tests|FullyQualifiedName~FilesM3Tests'
```

## Emoji picker and rendering

- Evaluate [emoji-picker-react](https://github.com/ealush/emoji-picker-react) (MIT) first for the React composer. [Emoji Mart](https://github.com/missive/emoji-mart) is an alternative. Use the selected library in native mode with same-origin data, loaded when the picker opens. Use English labels and Nexus design tokens. Keep picker focus and the text insertion point when inserting a character.
- Store emoji as Unicode sequences in messages and reactions. On iPhone and Mac, the device supplies Apple Color Emoji for glyphs supported by the installed OS. Windows WebView2 and other platforms use their own installed emoji fonts. [Unicode Emoji standard](https://www.unicode.org/reports/tr51/) · [Apple system font list](https://developer.apple.com/fonts/system-fonts/)
- Exact Apple artwork on Windows or Android would require a separate grant covering that artwork. A picker's MIT license applies to its code. Its `apple` style may fetch a separate spritesheet with its own terms. Keep the initial integration in native mode and verify that opening the picker and sending a message make no external emoji asset requests. [Emoji Mart picker options](https://github.com/missive/emoji-mart#options--props) · [iOS software license](https://www.apple.com/legal/sla/docs/iOS26_iPadOS26.pdf)
- If a shared style is desired across platforms, evaluate the actual asset coverage, browser support, and license of a pinned release. [Noto Emoji](https://github.com/googlefonts/noto-emoji) offers OFL-1.1 fonts and most images under Apache-2.0. [Microsoft Fluent Emoji](https://github.com/microsoft/fluentui-emoji) offers an MIT-licensed visual alternative. [Twemoji](https://github.com/jdecked/twemoji) offers CC BY 4.0 graphics with attribution. Serve approved assets from the Nexus origin, keep Unicode text as the fallback, and preserve required notices.
- Verify ordinary emoji, variation selectors, skin tones, flags, and joined sequences on iPhone Safari, Windows WebView2, and a supported Android or other desktop browser. Test paste, edit, copy, search insertion, message sync, and reactions where implemented. Verify the picker runs with the existing CSP and retains native rendering when a local graphics set lacks a glyph.
