# API and Realtime Contracts

- Status: active (living contract — M0.1 baseline)
- Last updated: 2026-11-24
- Scope: HTTP API conventions, pagination limits, SignalR hub contracts, and client/server version coordination.

## 1. Global HTTP conventions

- **Same-origin BFF:** All API routes are rooted under `/api/*` on the same origin as the React SPA.
- **Unknown API routes:** `/api/{**path}` returns HTTP `404` (never falls through to `index.html`).
- **Pagination cap:** Every list endpoint is cursor-paginated and capped at **at most 50 entries per page**.
- **Idempotency:**
  - Message sends use `client_msg_id` (see [`SYNC_PROTOCOL.md`](SYNC_PROTOCOL.md)).
  - Non-message mutating commands (e.g., create group, create community) use the `Idempotency-Key` header (M0.5).
  - Conflicting payloads under an existing key return HTTP `409 Conflict`.
- **Authentication & status errors:**
  - Unauthenticated requests to protected routes return `401`.
  - Authenticated requests failing `IAuthorizationService.Can` or `ActiveUserMiddleware` return `403` (or `401` on revoked session).
  - Sign-in failures return generic error messages that do not disclose username existence.

## 2. Route scopes

- Account, invitation preview and redemption, and Organization creation and listing start at `/api/auth` or `/api/organizations`. A newly registered account has zero memberships.
- Prefix the Organization resource paths in the endpoint table with `/api/organizations/{organizationId}` in place of `/api`. This covers Directory, HR, Communities, channels, posts, chat, files and sync. The server requires active membership and authorizes access to the named resource. `GET /api/organizations/{organizationId}/me` returns the membership profile.
- Prefix Personal Chat, files, sync and safety paths with `/api/personal` in place of `/api`. `GET /api/personal/people/directory` exposes accepted, active, unblocked external contacts, while `GET /api/personal/people/chat-candidates` returns the combined union of accepted contacts and active members sharing at least one active Organization (with `isContact` and `workspaceNames`) for unified DM and group-chat creation. Use `/api/personal/contacts/requests` to list incoming requests or request a connection by exact username, `PUT /api/personal/contacts/requests/{id}` to respond, and `POST /api/personal/contacts/links` or `POST /api/personal/contacts/links/redeem` to share or request a connection using a private link.
- Use `GET|POST /api/organizations/{organizationId}/invitations` to list or issue invitations, `DELETE /api/organizations/{organizationId}/invitations/{id}` to revoke, and `POST /api/organizations/invitations/{preview|redeem}` to open or confirm an invitation. The seven-day token is stored as a hash and redeemed once. TOTP enforcement on workspace settings is configurable via `NexusOrganizations:RequireAdminMfa` (default `false`).
- Use `GET /api/organizations/{organizationId}/members`, `DELETE /api/organizations/{organizationId}/members/{memberId}` and `PUT /api/organizations/{organizationId}/members/{memberId}/administrator` for scoped membership administration. Only the Owner can change a member's general administrator role.
- Organization, invitation, membership, contact and contact-request lists accept `limit` and the `after` cursor from `nextAfter`. New account and scope-management mutations that use browser cookie authentication require a CSRF token from `GET /api/auth/csrf`.

### Chat and Files pagination

- `GET /api/conversations` returns `hasMore` and `nextBefore`. When `hasMore` is true, pass `nextBefore.updatedAt` as `beforeAt` and `nextBefore.id` as `beforeId`. Tied timestamps sort by descending conversation ID.
- Pass `conversationId` to `GET /api/conversations` to resolve one eligible DM or Group Chat outside the loaded sidebar pages. A caller without current membership receives an empty list. For DM peers, `isBlockedByMe` describes the caller's own block only.
- `GET /api/conversations/{id}/files` returns `hasMore`, `nextBefore`, and `nextBeforeId`. When `hasMore` is true, pass `nextBefore` as `before` with `nextBeforeId` as `beforeId`. The timestamp-only `before` form remains available with an exclusive date boundary. Each page verifies current conversation access.

### People, Community, and feed pagination (`M6.23`)

- All opaque `cursor` endpoints return `{ items, nextCursor }` capped at 50 entries and reject malformed cursors with `400 invalid_cursor`.
- `GET /api/organizations/{orgId}/people/directory` supports `q`, `departmentId`, `excludeCommunityId` (verifying `CommunityAddOrRemoveMember` and Official Verified eligibility), and `cursor` ordered by `(score DESC, displayName ASC, id ASC)`.
- `GET /api/personal/people/chat-candidates` supports `q`, `excludeConversationId` (verifying `GroupAddMember`), and `cursor` ordered by `(displayName ASC, id ASC)`. `GET /api/personal/people/directory` supports case-insensitive `q` and `after` (`nextAfter`).
- `GET /api/organizations/{orgId}/org/departments` supports `cursor` ordered by `(name ASC, id ASC)`.
- `GET /api/organizations/{orgId}/communities` supports `discover=true|false`, `q`, `communityId`, `conversationId`, and `cursor` ordered by `(isOfficial DESC, name ASC, id ASC)`.
- `GET /api/organizations/{orgId}/communities/{id}/members` and `GET /api/conversations/{id}/members` support `cursor` ordered by `(role ASC, displayName ASC, userId ASC)`.
- `GET /api/organizations/{orgId}/channels/{conversationId}/posts` supports `cursor` ordered by `(isPinned DESC, createdAt DESC, id DESC)` and returns `{ items, hasMore, hasNewer, nextCursor, canPost, canManage }`. Pass `aroundPostId` (mutually exclusive with `before` and `cursor`) to load up to 50 posts centered around a target post. Passing conflicting cursors returns `400 invalid_cursor`.

### Authorized content links (`M6.25`)

- `GET /api/links/resolve?target={opaqueToken}` resolves an opaque Base64Url link token (`m` message, `p` feed post, `c` channel/community main feed) using current account status, Organization/Community/Conversation membership, `VisibleFromSeq` (`SEC-18`), and `SEC-20b` Official Community Verified checks, with `Cache-Control: no-store`.
- Any malformed, deleted, unauthorized, revoked, or cross-scope target returns the same generic `404 link_unavailable` response without disclosing content or membership.
- `GET /api/conversations/{id}/messages` accepts optional `aroundSeq` or `afterSeq` (mutually exclusive with `beforeSeq`, capped at 50 entries) and returns `hasNewer` and `nextAfterSeq` to load surrounding context for deep links.
- `GET /api/notifications/{id}/source` includes `messageId`, `seq`, and `targetLink` so Activity reuses the same deep-link navigation.

### Message search (`M6.6`)

- `GET /api/personal/messages/search` searches Personal Chat. `GET /api/organizations/{orgId}/messages/search` searches workspace chat and channel posts. Authorization and history boundaries apply inside the database query, including each reply's root and Verified status in Official Communities.
- Optional filters include `q` (message body or post title and body), `senderId`, `sender` (display name or username), `conversationId` (chat or channel), `from` (inclusive), `to` (exclusive), and `hasAttachment` (approved attached files). Text matching ignores Vietnamese accents and case. Text filters accept up to 120 characters each.
- The endpoint returns `{ items, nextCursor }` with `Cache-Control: no-store`. Results include `id`, `kind`, `conversationId`, `conversationTitle`, `authorId`, `authorName`, `createdAt`, `title`, `hasAttachment`, `preview`, and `sourceLink`. Pages use an opaque `cursor` ordered by `(createdAt DESC, id DESC, kind DESC)` with `limit` up to 50. Opening a result rechecks authorization.

### Quick switcher (`M6.7`)

- `GET /api/conversations?q=` filters current chat memberships by group or Self Chat title, or by the DM peer's display name or username. The optional filter accepts up to 120 characters, ignores case and Vietnamese accents, and applies before cursor pagination.
- The quick switcher uses the Personal conversation list, Organization member Community lists, and Personal chat candidates. Channel results resolve through the existing authorized channel link. `Ctrl+K` or `Cmd+K` opens the switcher from the workspace. A composer consumes its own link-insertion shortcut when focused.

### Sidebar organization and previews (`M6.26`)

- `GET /api/sidebar?surface=chat|communities` returns `{ surface, sections, items }` (`Cache-Control: no-store`), capped at 50 sections per surface, joining items against current active conversation/community/organization memberships (plus `SEC-20b` Verified status for Official communities).
- `POST /api/sidebar/sections`, `PUT /api/sidebar/sections/{sectionId}`, `DELETE /api/sidebar/sections/{sectionId}`, `PUT /api/sidebar/items/{targetId}`, and `PUT /api/sidebar/reorder` require antiforgery, authorize target access on write, and persist per-user Favorites, named sections, hide/show (preserving history and notification preferences), and custom ordering. Revoking group, community, or organization membership deletes stale sidebar items.
- `GET /api/conversations` supports `unreadOnly=true` (filtering by live `nextSeq > MAX(lastReadSeq, visibleFromSeq)`) and includes `lastMessagePreview` strictly within `seq > visible_from_seq` (`SEC-18`).
- `GET /api/communities` includes `latestPostPreview` only for authorized members (`!discover` and Verified for Official communities).

### Read state during message send

`POST /api/conversations/{id}/messages` accepts `preserveReadState: true`. The SPA uses it so sending or replaying a message in the background preserves the sender's read cursor. It advances that cursor through `PUT /api/conversations/{id}/read` as the conversation is displayed. Senders that omit the flag continue to advance their own read cursor at commit. The flag controls read behavior on the first commit and does not change message payload identity.

For chat reactions, URL-encode the emoji segment. Empty values, control characters, and values longer than 32 UTF-16 code units return `400 invalid_emoji`. A missing or pre-join message in an accessible chat returns `404 message_not_found`. A recalled message returns `409 message_recalled`. A DM block denies reaction writes from both accounts. Channel posts use their existing post reaction route.

Message history includes `reactions: [{ emoji, count, reactedByMe }]` per message, ordered by the oldest remaining reaction for each emoji. The counts and the page's `changeSeq` come from the same snapshot. Recalled messages have an empty reaction array.

For threads, send replies with `POST /api/conversations/{id}/messages` and `parentMessageId` set to the root message ID. Reply writes require CSRF. A reply to another reply returns `400 nested_thread_not_allowed`. The root and reply must both be within the caller's visible history. Main message pages contain roots and include each root's reply count, latest reply time and sequence, and the caller's follow and unread state.

The thread page accepts one of `beforeSeq`, `afterSeq`, or `aroundSeq` and returns `{ parent, items, hasMore, hasNewer, nextBeforeSeq, nextAfterSeq, changeSeq, state }`. Follow/unfollow and `PUT .../thread/read` (body `{ lastReadReplySeq }`) return `{ conversationId, parentMessageId, isFollowing, lastReadReplySeq, lastReplySeq, hasUnread, version }`. The thread read cursor advances monotonically and is capped at the latest reply. Conversation lists and reconcile expose `latestMainSeq` alongside the shared `nextSeq`. Main unread badges count only roots.

Resolving an authorized link to a reply returns its `parentMessageId` and `parentSeq` so the client can open the thread and locate the reply. Shared content and download endpoints also check access to the thread root.

Edits and recalls require one quoted positive version from the message DTO, for example `If-Match: "1"`. A missing header returns `428 precondition_required`. An invalid header returns `400 invalid_if_match`. A stale version returns `412 message_version_conflict` with the current `ETag`. An expired author window or an already recalled message returns `409`. A recall keeps the timeline position and renders **This message was recalled**. Recalled content is unavailable to content link and attachment consumers, and a recalled last message uses the same marker in the conversation preview.

Pinned and Saved message lists accept the paired `beforeAt` and `beforeId` cursor and `limit` up to 50. Each item includes `messageId`, `conversationId`, `bodyPreview` and an authorized `sourceLink`. The server checks current membership and the visibility floor of both a reply and its root. Message pages include `isPinned`, `isSaved` and `savedVersion`. A pin write returns `{ delta, changeSeq }`. A save write returns the versioned state for the caller's account. `GET /api/conversations/{id}/saved-state` accepts up to 50 `ids` query values for reconnect recovery and returns only readable message states.

The manual unread marker does not rewind `lastReadSeq`. The chat list and reconnect response include `manualUnreadFromSeq` and `manualUnreadVersion`. `PUT /read` may include `manualUnreadVersion` to clear that observed marker when `lastReadSeq` reaches it. `ReadStateUpdated` delivers `{ conversationId, lastReadSeq, unreadCount, manualUnreadFromSeq, manualUnreadVersion }` to the caller's sessions. The `Unread` filter uses both the normal root-message cursor and the manual marker.

### Ownership transfers

Group Chat and Community transfer endpoints accept `{ newOwnerUserId }` from the current Owner. The recipient must be an active member, and an Official Community recipient must also be Verified. The former Owner becomes Admin in the same transaction as the new Owner is promoted. A transfer that loses its eligibility returns `403` or `409`. Member lists include `isActive` for recipient selection.

### Operator-issued password reset

`POST /api/auth/reset-password` accepts `{ token, newPassword }` in the JSON body. An unknown, expired, or redeemed code returns `400 invalid_reset_token`. Password validation failures return `400 password_policy_failed` and leave the code redeemable. A successful reset consumes the code and revokes existing BFF sessions in the same transaction as the password update. It returns `{ reset: true }` and the user signs in again.

### Deployment Monitor

All paths below are under `/api/monitor`. The user-facing read endpoints require a deployment Monitor grant. Mutations require the execution grant, verified MFA, and antiforgery.

| Endpoint | Contract |
|---|---|
| `GET /capabilities` | Environment label, execution grant, MFA state, and runner configuration status. |
| `GET /performance?range=5m` | Deployment aggregate samples. Ranges are `5m`, `15m`, and `1h`. |
| `GET /runs` | Up to 50 newest runs per page. Pass `nextCursor` as `before` for the next page. |
| `POST /runs` | Submit `requestId` and a typed `configuration`. The API accepts the reserved sandbox profiles and returns `202` for an idempotent start or `409` for a conflicting start. |
| `GET /runs/{id}`, `GET /runs/{id}/performance` | Run state, sanitized lifecycle events, and sandbox aggregate samples. |
| `POST /runs/{id}/stop` | Persist an idempotent stop request and return `202`. The runner reports the terminal result and cleanup. |
| `GET /runs/{id}/report?format=json` | Download a filtered run report. `html` returns the same model as a standalone HTML report. |
| `POST /runner/claim`, `POST /runner/runs/{id}/heartbeat`, `POST /runner/runs/{id}/result` | The dedicated machine principal claims, renews, and reports a matching lease generation. |

## 3. SignalR hub contract

- **Origin enforcement:** Reject WebSocket connections whose `Origin` header does not match the configured same-origin host (`M0.3`).
- **Active user enforcement:** `ActiveUserHubFilter` checks account status and security stamp on connect and every hub invocation; password change or disabling an account aborts open connections (`M1.5`, `M1.6`).
- **Scope and group naming.** Connect to `/hubs/personal/messaging` (single-window default) or `/hubs/organizations/{organizationId}/messaging`. On `/hubs/personal/messaging`, the server subscribes the connection to `scope:{Guid.Empty}:user:{userId}` plus `scope:{orgId}:user:{userId}` for each active Organization membership (refreshable via `RefreshOrganizationSubscriptions()`). It reads active recipients from PostgreSQL before sending `ConversationChanged(conversationId, changeSeq, message?, delta?)`, `ReadStateUpdated(conversationId, lastReadSeq)`, and `CommunityFeedChanged(conversationId, delta?)`. Revoking an Organization membership immediately closes that Organization's scoped connections, removes live personal-hub connections from `scope:{orgId}:user:{userId}`, and pushes `OrganizationAccessRevoked(organizationId)`.
- **Chat reaction (`M6.1`).** `ConversationChanged` carries `delta: { type: "reaction", messageId, seq, emoji, userId, reacted }` for active members authorized to see the target message. `userId` identifies the account whose reaction changed.
- **Chat thread (`M6.2`).** `ConversationChanged` carries `delta: { type: "thread_reply_created", messageId, seq, message, replyCount, lastReplyAt, lastReplySeq }`. Here `messageId` and `seq` identify the root and `message` contains the new reply. `ThreadStateUpdated` carries the same versioned per-user state as the thread write endpoints and goes to the caller's sessions only.
- **Message edit and recall (`M6.3`).** `ConversationChanged` carries `delta: { type, messageId, seq, visibilitySeq, parentMessageId, version, body, editedAt, deletedAt }`, where `type` is `message_edited` or `message_recalled`. A recall sends an empty body.
- **Presence & typing (`M2.10`):** In-memory `PresenceAndTypingTracker`; `SendTyping(conversationId)` verifies DB membership via `IAuthorizationService.Can` and throttles `TypingIndicator` to 1 event per 2 seconds per `(user, conversation)`.
- **Group access revocation (`M6.17`).** After a removal or leave commits, `ConversationAccessRevoked` sends `{ conversationId, organizationId }` only to the affected account in that scope. `organizationId` is null for Personal Chat. The client drops local work and history for the affected chat and still verifies access during HTTP reconciliation.
- **Role refresh (`M6.21`).** Group transfer emits a `ConversationChanged` nudge. Community transfer emits `CommunityFeedChanged` on the main feed with `delta: { type: "ownership", communityId }`. Authorized clients refresh roles and an open members drawer using the normal list endpoints.
